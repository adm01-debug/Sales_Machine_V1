## Findings

### 🔴 F1 — CHECK `campaign_targets.status` sem 'completed'  ✅ FIXED (mig 013)
Trigger `tg_sync_target_status` grava `status='completed'` para estados finais.
Constraint anterior aceitava só `queued/running/done/failed/paused` → todo encerramento de campanha (`replied`, `stopped`, `lost`, `completed`) explodia. Migration 013 recria a constraint com `'completed'` incluído.

### 🔴 F2 — Triggers duplicados em `campaign_targets`  ✅ FIXED (mig 013)
`trg_log_target_state_change` (BEFORE) + `trg_campaign_targets_state_log` (AFTER) chamavam a mesma função. Idem para `trg_sync_target_status` + `trg_campaign_targets_status_sync`. Cada transição gravava 2 audit rows e sincronizava 2x. Migration 012 tentou dropar mas foi revertida por edição posterior — migration 013 dropa em definitivo.

### 🔴 F10 — Canal email era no-op  ✅ FIXED (patch)
`tick-cadence.ts` só tratava `whatsapp` e `sms` no envio real. Passos com `channel='email'` incrementavam `sender_health.sent` sem chamar nenhuma API. Corrigido:
- Adicionado `singuClient.sendEmail(...)` em `src/integrations/external/singu.server.ts`.
- Adicionado branch `else if (step.channel === "email")` em `tick-cadence.ts`.

### 🟡 F8 — `enqueueBatchProspection` quebrava em duplicata  ✅ FIXED (patch)
Insert em `campaign_targets` sem `ON CONFLICT` violava `UNIQUE(campaign_id,entity_id)` ao re-selecionar empresas. Trocado por `upsert(..., { onConflict:"campaign_id,entity_id", ignoreDuplicates:true })`.

### 🟡 F12 — Linter `Signed-In Users Can Execute SECURITY DEFINER`  ✅ PARTIAL (mig 013)
Revogado `EXECUTE` de `handle_new_user()` para `authenticated`/`anon`/PUBLIC (trigger em `auth.users`, nunca é chamada diretamente). `has_role()` permanece SD callable — **REQUERIDO** pelas policies RLS.

### 🟡 F9 — Edge functions Deno duplicam TSS routes
`supabase/functions/{webhook-lux,webhook-singu,webhook-fatorx,tick-cadence,tick-marketing,approve-touchpoint,handoff-deal,singu-send}` sobrepõem `src/routes/api/public/...`. Fonte da verdade é TSS. Ação pendente: remover as edge functions (não executa hoje pois pg_cron aponta pra rota TSS; nenhum webhook externo aponta pra edge). Deixadas como referência histórica.

### 🟡 F5 — LGPD/consent stack ausente
Doc do projeto referencia `check_consent()`, `consent_ledger`, `delete_entity_personal_data()`, `stop_word_lists`, `agent_identity_config`. Nenhuma existe no banco. `tick-cadence` não bloqueia envio por opt-out. **Recomendação**: entrar como item da fase 11+ (compliance).

### 🔵 F11 — `channel_quotas` vazia
Seed da migration 012 falhou silenciosamente (tenta inserir sem `user_id` NOT NULL). Não afeta hoje (worker usa `compute_daily_cap`+`sender_health`). Quando quotas por usuário forem ativadas, exigirá seed com `user_id`.

### 🔵 F3-warning — Linter "Extension in Public"
`pg_cron`/`pg_net` no schema `public` — design da Supabase. Não corrigível sem quebrar cron. Aceito com justificativa.
